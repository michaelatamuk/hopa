# HOPA for Windows 0.1.0

First Windows build. The window is a HOPA client: conversations, approvals, the
run view, settings, the phone target through the PC bridge and the PC itself
through UI Automation.

## What works

- Chat with the HOPA layout: sidebar, conversation list, bubbles, composer
  (Enter sends, Shift+Enter breaks the line).
- Conversations persist across restarts; search, rename, export, delete.
- Approvals: a payment stops, the sheet explains the consequence, deny stops the
  action, a pending approval is denied on the next start, a silence of 120 s
  counts as deny.
- Run records per turn with the hash chain; the Run button shows the steps.
- Settings: bridge address and token (Credential Manager), model provider, base
  URL, name, key (Credential Manager), tone. Window position and size are kept.
- Phone target: the bridge `AdbDevice` launches and reads apps on a paired
  phone; one 401 refresh rotates the token.
- PC target: real UI Automation observation and actions, with an honest refusal
  on the lock screen and other secure surfaces.
- Tray icon with Open/Exit and a balloon for answers that arrive unfocused;
  Copy and Speak for the last answer; `Ctrl+N`, `Ctrl+F`/`Ctrl+K`, `Esc`.

## Known gaps

- **No code signing**: Windows SmartScreen will warn, and the `uiAccess` helper
  for elevated windows is not built, so HOPA refuses elevated windows instead of
  acting in them.
- The answer text comes from a scripted model until a provider key is entered in
  Settings.
- Dictation is wired (microphone -> bridge `/transcribe`) but was not verified on a real microphone; no
  Windows share sheet (Copy covers the clipboard path).
- No screenshots on secure surfaces; no clean-VM E2E yet.
- The MSI shows the repository LICENSE on the WiX licence page; `LICENSE.txt` is also shipped in the folder.
